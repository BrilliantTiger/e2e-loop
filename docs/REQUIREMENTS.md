# e2e-loop 요구사항 확정본 (v1.0)

웹 최종 E2E 테스트를 **이슈가 0이 될 때까지** 라운드로 반복하는 MCP 도구다.

```
1라운드 → 수정 → 2라운드 → 수정 → 3라운드 → … → 이슈 0
```

- 작성일: 2026-10-14
- 상태: **확정**(2026-10-14, 사용자 확정). 이후 변경은 이 문서를 고치고 맨 아래 "변경 이력"에 적는다. 구현은 아래 "구현 순서"대로 기능 단위로 진행하고, 단계마다 보고한다.
- 저장소: `BrilliantTiger/e2e-loop` (공개). TypeScript + bun. 웹 전용.

## 동작 흐름

1. **환경 점검** — 필요한 도구(Playwright 브라우저, Ego, ffmpeg, 컴퓨터 제어)를 점검한다. 없으면 설치하거나 설치 방법을 안내한다.
2. **테스터 세션 시작** — Orca skill로 새 세션을 띄운다. 없으면 "새 세션 / 여기서"를 묻는다.
3. **입력 받기** — 사용자에게 실행되는 웹 주소(필수)와 기획서·디자인·기능정의서·코드를 요청한다. 웹 주소와 근거 하나 이상이 없으면 시작하지 않는다.
4. **분석과 시트 작성** — 문서·코드·결과물(웹)을 훑어 모든 페이지의 이벤트를 찾고 테스트 시트를 만든다. 시트를 사용자에게 한 번 보여 주고 바로 시작한다.
5. **시작 전 질문** — 데이터를 초기화할지(기본: 안 함), 라운드 상한(기본: 10), 로그인·테스트 계정이 필요한지를 묻는다. "영상·스크린샷에 남으니 테스트 데이터와 테스트 계정만 입력하라"고 안내한다.
6. **라운드 실행** — 기본 Headed로 시트를 처음부터 끝까지 돌린다. 영상을 녹화하고 현황판에 진행을 보여 준다. 기능 단위의 케이스가 모두 통과하면 그때그때 보고한다.
7. **라운드 결과물** — 사람이 보기 편한 시트와 AI용 시트(이슈별 오류 상황 상세)를 쓴다.
8. **수정** — 개발 에이전트가 AI용 시트를 받아 코드를 고친다. 테스터는 고치지 않는다. 그 사이 사용자가 E2E에 관해 한 말은 다음 라운드부터 적용한다.
9. **종료** — 마지막 전체 라운드의 이슈가 0이면 끝난다. 상한에 닿거나 같은 이슈가 7라운드 연속(`repeatLimit`, 기본 7 — 변경 이력 15번)이면 사용자에게 올린다.

## 확정 요구사항

### 실행 환경

| 항목 | 확정 내용 |
|---|---|
| 브라우저 | **Chrome 기반 전부**(Chrome·Chromium·Edge 등)를 Playwright로, **Ego**는 Ego 자체 API로 쓴다. 사용자가 하나를 고른다. Safari는 제외하고 지원하지 않음을 명시한다. |
| 실행 모드 | 기본은 **Headed**. Headless는 사용자가 요구할 때만. 화면 없는 환경이면 자동 전환하지 않고 묻는다. |
| 사용자 개입 | 탐색·실행은 무인. 로그인·권한·계정이 필요하면 **진행 중에 사용자에게 묻는다.** 만들라고 하면 **만드는 방법(화면·API·DB 스크립트)을 먼저 묻고** 테스트 계정을 만들어 쓰고 끝나면 지운다. macOS 권한 허용은 테스트 전 설정 단계라 "개입"으로 세지 않는다. |
| 설치 | Playwright 브라우저는 **자동 설치**한다. e2e-loop MCP는 설치 때 **e2e-loop를 설치한 클라이언트(Claude·Codex 등)에 자동 등록**한다. 클라이언트를 따로 구분하지 않는다. ffmpeg가 없으면 사용자에게 묻고 설치한다. Ego(MCP가 아니라 스킬 + ego-browser 명령)와 컴퓨터 제어(클라이언트 내장 기능)는 설치할 패키지가 없어 보이는지 점검만 하고, 앱 설치와 OS 권한 허용은 안내한다. |

### 수행 주체

| 항목 | 확정 내용 |
|---|---|
| 테스터 세션 | 기존 에이전트가 아니라 **새 세션의 AI**가 진행한다. Orca skill이 있으면 그것으로 띄운다. 없으면 "새 세션 / 여기서"를 묻는다. 여기서 → 바로 진행. 새 세션 → MCP가 붙은 AI를 실행하거나 바로 쓸 수 있는 명령어를 준다. (`orca terminal create --command`로 가능함을 확인했다.) |
| 세션 수명 | 기본은 **한 세션을 유지**하고 상태는 `.e2e/` 파일에 둔다. 사용자가 새 세션을 명시하면 그때 새로 띄운다. |
| 역할·모델 | 테스터는 **코드를 고치지 않는다.** 수정은 개발 에이전트가 AI용 시트를 받아 한다. 모델은 고정하지 않고 사용자 환경의 기본 모델을 쓴다. |
| 문서 요청 | 테스터가 켜지면 사용자에게 기획서·디자인·기능정의서를 달라고 요청하고, 받은 것을 기반으로 한다. |

### 분석과 시트

| 항목 | 확정 내용 |
|---|---|
| 최소 진행 조건 | **실행되는 웹 주소 + 근거 하나 이상**(기획서·디자인·기능정의서·코드 중). 못 채우면 시작하지 않고 요청한다. 근거 우선순위는 기획서·디자인 → 기능정의서 → 개발된 사이트. |
| 분석 | 코드가 주어지면 코드를 분석한다. 문서·코드·결과물(웹)을 아주 상세하게 훑어 **모든 페이지의 이벤트**를 찾고 시트를 쓴다. |
| 이벤트 범위 | 클릭·입력·선택·토글·탭·폼·모달에 더해 **API 요청·응답값, 다운로드·업로드** 등. 브라우저 밖 OS 창(다운로드·파일 선택)은 컴퓨터 제어 도구가 맡는다. 테스트 전에 이 도구가 동작하는지 점검하고, 안 되면 권한을 요구하며 스킵할지 허용할지 묻는다. 허용하면 포함해 진행하고, 스킵하면 스킵으로 둔다. |
| 시트 확정 | 시트를 사용자에게 **한 번 보여 주고 바로 시작**한다. 기본은 묻지 않는다. 사용자가 원하면 확인을 받고 시작한다. |
| 기능 단위 | 기능 단위는 코드·디자인·웹 분석에서 뽑는다. |

### 라운드

| 항목 | 확정 내용 |
|---|---|
| 반복 | 1라운드 → 수정 → 2라운드 → … 이슈 0에 수렴할 때까지. |
| 이슈의 정의 | **이슈 = 실패 + 검증 못 한 것 + 사용자가 승격한 경고.** 가끔 실패하는 시험(flaky)은 3번 재시도한다(모두 통과면 통과, 일부만이면 "불안정" 이슈). 디자인 일치는 기계 판정이 가능한 것만 자동으로 본다. **스킵한 케이스는 이슈가 아니다.** (해석: 스킵 = 규칙이나 사용자 선택으로 일부러 돌리지 않은 것, 검증 못 한 것 = 돌리려 했으나 환경·차단으로 판정하지 못한 것.) |
| 상한 | 시작 전에 사용자에게 묻고, 기본은 **10라운드**. 같은 이슈가 7라운드 연속(`repeatLimit`, 기본 7 — 변경 이력 15번)이면 사용자에게 올린다. |
| 데이터 | 시작 전에 **초기화할지 묻는다.** 기본은 **초기화하지 않고 진행**이다. 초기화 명령은 프로젝트마다 한 번 등록한다. |
| 파괴적 동작 | **로그아웃**은 테스트하고 다시 로그인한다. **삭제**는 테스터가 테스트 중 등록한 데이터만 대상으로 한다. 그 밖의 파괴적 동작은 **스킵**으로 두고 이슈로 세지 않는다. |
| 부분 라운드 | 일부 케이스만 다시 돌리는 부분 라운드를 **수정 확인용으로 허용**한다. 이슈 0 판정과 종료는 전체 라운드로만 한다. |
| 도중 코드 변경 | 라운드 도중 코드가 바뀌어도 **무효로 하지 않는다.** 그 라운드는 그대로 진행하고, 바뀐 코드는 다음 라운드에서 확인한다. |
| 사용자 요청 | E2E에 관한 사용자 말은 **다음 라운드부터** 적용한다. "지금 라운드부터"라고 하면 **처음부터 다시 할지, 지금 흐름에서 적용할지 먼저 묻고** 적용한다. |

### 결과물

| 항목 | 확정 내용 |
|---|---|
| 라운드 시트 | **사람용**(보기 편한 문서)과 **AI용**을 둘 다 쓴다. AI용은 이슈마다 오류 상황을 상세히 남긴다: 재현 단계·기대값·실제값·API 요청과 응답·콘솔 로그·스크린샷과 영상 위치. 개발을 단계적으로 시킬 수 있게 쪼갠다. |
| 영상 | 모든 테스트를 녹화하고 근거로 쓴다. **Chrome 계열은 Playwright 내장 녹화**(recordVideo, 페이지 화면만 저장), **Ego는 macOS 창 녹화**(`screencapture -v -l<창ID>`로 창 하나만 녹화 → ffmpeg로 대기 구간을 줄이고 챕터 파일 생성). 형식은 둘 다 mp4(h264) + 챕터 파일. |
| 증거 기록 | 영상·스크린샷에 **커밋·시각·케이스 id·해시**를 기록한다. 보관은 라운드 단위로 하고, 용량 상한 전에 알린다. |
| 보고 | 기능 단위의 케이스가 모두 통과하면 보고한다. |

### 현황판

| 항목 | 확정 내용 |
|---|---|
| 접속 | localhost가 아니라 **내부망 IP**(192.168.x.x·10.x.x.x)로 띄워 같은 망 어디서든 접속한다. **접속 토큰을 두고, 토큰 없는 접속은 막는다.** 시작 전에 "테스트 데이터와 테스트 계정만 입력하라"고 안내한다. |

## 구현 순서

기능 단위로 8단계에 나눠 만든다. 한 단계가 끝날 때마다 사용자에게 보고한다.

1. **환경 점검·설치** — 도구 점검(ffmpeg 포함, 없으면 묻고 설치), Playwright 브라우저 자동 설치, e2e-loop MCP를 e2e-loop를 설치한 클라이언트(Claude·Codex 등)에 자동 등록, 앱·OS 권한 안내, 브라우저 선택.
2. **테스터 세션** — Orca skill로 새 세션 실행, 없으면 "새 세션 / 여기서" 질문, 한 세션 유지와 새 세션 명시 규칙, 시작할 때 문서·웹 주소를 요청하고 최소 진행 조건 확인.
3. **분석과 시트** — 코드 분석, 사이트 전수 탐색, 이벤트 범위 확장(API·다운로드·업로드), 시트 작성, "한 번 보여 주고 시작".
4. **라운드 실행** — Headed 기본, 시작 전 질문(데이터 초기화·상한·테스트 계정 안내), 영상 녹화(Chrome 계열·Ego), 증거 기록, 파괴적 동작 규칙(로그아웃 테스트, 자기 데이터만 삭제, 나머지 스킵).
5. **결과물** — 사람용 시트, AI용 시트(이슈별 상세 기록, 단계별로 쪼갠 개발 지시), 이슈 정의(재시도 3번, 승격한 경고).
6. **현황판** — 내부망 IP로 띄우기, 접속 토큰, 진행·지금 화면·이슈 추이.
7. **요청 반영 규칙** — 다음 라운드가 기본, "지금부터"는 질문. 프로토타입에 이미 있고 새 구조에 연결한다.
8. **종단 시험** — 버그를 심은 데모 사이트로 1라운드 실패 → 수정 → 2라운드 통과. Ego 경로도 시험한다.

## 프로토타입 현황

| 구분 | 내용 |
|---|---|
| 동작 확인함 | 버그 4개를 심은 데모 사이트에서 Playwright Chromium으로 1라운드에 4개를 모두 발견 → 수정 → 2라운드 이슈 0 → 완료 판정 통과. 라운드 도중 요청은 다음 라운드에 적용하고, "지금부터"는 방식을 되묻는다. 삭제·로그아웃 같은 파괴적 요소는 탐색 중 누르지 않고 표시만 한다. |
| 일부만 확인 | Ego 브리지(Ego 안에 작은 HTTP 서버를 띄워 명령을 보내는 방식)는 이동·제목 읽기까지만 확인했다. Ego로 전체 종단 시험은 하지 못했다. |
| 재사용 | 브라우저 어댑터, 케이스 실행기, 판정 규칙, 라운드 오케스트레이터, 완료 판정, 요청 반영 규칙, 보고서 틀. |
| 다시 만들 것 | 기본 Headless → Headed, AI용 시트(오류 상세 기록), 이벤트 범위, 현황판 localhost → 내부망 IP, 스킬(새 세션 구조), 라운드 도중 코드가 바뀌면 그 라운드를 무효로 하던 처리 제거, 스킵을 이슈에서 제외(완료 판정 변경), 파괴적 동작 규칙(로그아웃은 테스트, 삭제는 테스터가 등록한 데이터만, 나머지 스킵). |
| 새로 만들 것 | 코드 분석, Edge 채널, 테스터 세션 실행(Orca), MCP 자동 등록(Claude·Codex), 기능 단위 보고, Ego 창 녹화, 증거 해시, 시트 보여 주기, 테스트 계정 생성·삭제, 현황판 접속 토큰, 파괴적 동작 스킵·자기 데이터 삭제. |

## 구현 전에 확인한 세부 (모두 확정)

처음에는 제안이었으나 사용자가 모두 확정했다. 확정한 내용은 위 "확정 요구사항" 표에도 들어 있다.

| # | 세부 | 확정 | 닿는 단계 |
|---|---|---|---|
