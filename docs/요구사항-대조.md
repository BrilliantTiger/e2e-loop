# 확정 요구사항 대조 (8단계 완료 시점)

`docs/REQUIREMENTS.md`(v1.0 확정본과 변경 이력)의 항목을 하나씩 구현·시험과 맞춰 본 표다.

- **충족**: 구현했고 시험으로 확인했다.
- **조건부**: 구현했지만 환경이나 시험 범위 때문에 확인하지 못한 부분이 있다. 아래 "한계"에 적었다.
- 시험 이름은 `test/` 아래 파일이다. 시험은 실제 `~/.claude.json`, `~/.codex`를 건드리지 않는다.

## 8단계 종단 시험 결과

버그 4개(모달이 안 닫힘, 통계 API 500, 내보내기 JS 오류, 깨진 링크)를 심은 데모 사이트에서 전체 라운드(33건)를 돌렸다.

| 브라우저 | 1라운드 | 수정 후 2라운드 | 완료 판정 | 영상 |
|---|---|---|---|---|
| Chromium | 이슈 5 | 이슈 0 | 통과 | 33건 모두 mp4(h264)+챕터 |
| Google Chrome | 이슈 5 | 이슈 0 | 통과 | 33건 모두 mp4(h264)+챕터 |
| Ego | 이슈 5 | 이슈 0 | 통과 | 없음(Ego 창을 찾지 못해 이유를 경고로 남김), 스크린샷도 캡처 무응답으로 없음 |

심은 버그는 4개인데 1라운드 이슈가 5개인 것은 통계 API 500 하나가 "통계를 누르면 항목 수가 나온다" 기획서 케이스와 "통계 새로고침 버튼" 점검 케이스 둘을 함께 실패시켰기 때문이다. AI용 시트는 이 둘을 한 작업으로 묶는다(5단계).

세 경우 모두 사람용·AI용 시트, 토큰 없는 현황판 접속 거부, 토큰 있는 접속에서 진행 중 상태와 끝난 뒤 이슈 추이 확인까지 확인했다. 수정 커밋이 2라운드의 증거(커밋 해시)에 반영됐다.

## 한계

1. **Ego 영상은 항상 남지 않는다.** Ego는 한 창에서 한 번에 한 작업만 보여 준다. 다른 에이전트가 그 창을 쓰는 동안은 이 도구의 작업이 보이지 않아 창을 찾지 못한다. 이때 화면 캡처도 응답하지 않을 수 있다. 사용자 창을 가로채지 않으려고 앞으로 끌어오지 않는다. 이 경우 이유를 경고로 남긴다.
2. **실제 환경을 건드리는 부분은 가짜로만 시험했다.** Claude·Codex 설정 등록, Orca 새 터미널 실행, 컴퓨터 제어 권한이 그렇다.
3. **현황판을 다른 기기에서 열어 보지 못했다.** 내부망 IP에 바인딩된 것과 localhost가 거부되는 것까지만 확인했다.
4. **코드 분석은 근사다.** 지원하지 않는 프레임워크는 라우터를 찾지 못했다고 알리고, 이벤트·API 후보만 뽑는다.
5. **Edge는 설치돼 있지 않아 실행하지 못했다.**
