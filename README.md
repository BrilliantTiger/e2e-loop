# e2e-loop

웹 최종 E2E 테스트를 **이슈가 0이 될 때까지** 라운드로 반복하는 MCP 도구 + 스킬.

```
1라운드 → 수정 → 2라운드 → 수정 → 3라운드 → … → 이슈 0
```

- 요구사항(확정): [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md)
- 상태: 구현 진행 중. 기능 단위로 만들고 기능 단위로 push 한다.

## 지원 브라우저

Chrome 기반 전부(Chrome·Chromium·Edge 등)는 Playwright 로, Ego 는 Ego 자체 API 로 쓴다. 사용자가 하나를 고른다. **Safari 는 지원하지 않는다.**

## 설치

```sh
git clone git@github.com:BrilliantTiger/e2e-loop.git
cd e2e-loop
sh install.sh
```

`install.sh` 가 하는 일:

1. `bun` 이 없으면 설치한다.
2. `bun install` 로 의존성을 설치한다.
3. 환경을 점검한다: Playwright 브라우저, Chrome, Edge, Ego, ffmpeg, git, Orca, macOS 권한.
4. 빠진 **Playwright 브라우저는 자동 설치**한다.
5. **ffmpeg 처럼 설치 전에 물어야 하는 것**은 설치하지 않고 질문으로 돌려준다. 승인하면 `sh install.sh --confirm ffmpeg`.
6. e2e-loop MCP 를 **설치된 모든 클라이언트**(Claude Code, Codex)에 등록한다. 이미 있으면 건너뛴다.
7. 테스터 스킬(`skills/e2e-loop`)을 Claude Code(`~/.claude/skills`)와 Codex(`~/.agents/skills`)에 링크한다. 저장소를 `git pull` 하면 스킬도 함께 갱신된다. 같은 이름의 실제 폴더가 있으면 덮어쓰지 않고 알린다.
8. 직접 해야 하는 것(Ego 앱 설치, macOS 권한 허용)은 안내만 한다.

점검만 하려면 `bun src/cli.ts doctor`, 실행 계획만 보려면 `--dry-run`.

### 테스터 세션

E2E 는 코드를 고치는 에이전트가 아니라 **새 세션의 AI(테스터)** 가 진행한다.

- `e2e_session_start`: Orca 가 있으면 새 터미널에서 AI 를 띄운다. 없으면 "새 세션 / 여기서"를 묻고, "새 세션"이면 실행할 명령을 준다. 세션이 이미 있으면 그대로 유지한다(사용자가 새 세션을 명시할 때만 `new_session`).
- `e2e_intake`: 웹 주소와 기획서·디자인·기능정의서·코드를 받아 **최소 진행 조건**(실제로 열리는 웹 주소 + 근거 하나 이상)을 검사한다. 못 채우면 시작하지 않고 사용자에게 요청한다.
- 상태는 대상 프로젝트의 `.e2e/session.json`, `.e2e/intake.json`, `.e2e/sources.json` 에 있다.
- 터미널에서: `bun src/cli.ts session --mode new`, `bun src/cli.ts intake --baseUrl URL --materials '[{"kind":"plan","location":"docs/plan.md"}]'`

### 분석과 시트

- `e2e_discover`: 사이트를 돌며 클릭·입력·선택·토글·탭·폼·모달에 더해 **API 요청·응답(fetch·XHR), 다운로드 링크, 파일 입력**을 모은다.
- `e2e_analyze`: 코드(Next·React Router·Vue Router·Nuxt·SvelteKit·정적 HTML)에서 화면·이벤트·API·다운로드/업로드 후보를 뽑아 사이트 탐색 결과와 대조한다. 코드에는 있는데 링크로 안 닿는 화면은 직접 열어 확인하는 케이스로 만든다. 새 프레임워크는 `src/analysis/code.ts` 의 `ROUTE_EXTRACTORS` 에 추가한다.
- `e2e_os_check`: 다운로드·파일 선택이 브라우저 밖 OS 창을 거치는지 테스트 전에 점검한다. Chrome 계열은 Playwright 가 직접 처리하므로 해당 없다. Ego 에서 컴퓨터 제어가 안 되면 권한 안내와 함께 허용/스킵을 묻는다.
- `e2e_sheet`: 화면 → 기능 단위 → 케이스로 묶은 시트(`.e2e/sheet.md`)를 만든다. 케이스마다 근거(문서 절·코드 위치)가 있다. 요약을 한 번 보여 주고 바로 시작하며, 확인 후 시작을 원하면 `confirm_before_start`.

### 라운드 실행

- 시작 전 질문 `e2e_prestart`: 데이터 초기화(기본 안 함, 초기화 명령은 프로젝트마다 한 번), 라운드 상한(기본 10, 전체 라운드만 셈), 로그인·테스트 계정, "영상·스크린샷에 화면이 그대로 남으니 테스트 데이터와 테스트 계정만 입력" 안내. 마치기 전에는 `e2e_round_start` 가 시작되지 않는다.
- 기능 단위의 케이스가 모두 통과하면 그때그때 보고한다: 현황판 로그에 "기능 완료"가 뜨고, `e2e_round_status` 의 `feature_reports.report_to_user` 가 한 번씩 알려 준다(실패가 섞인 기능은 보고하지 않는다).
- 기본은 Headed. Headless 는 `headless=true` 로 요구할 때만. 화면 없는 환경(Linux, DISPLAY 없음)이면 자동으로 바꾸지 않고 묻는다.
- 이슈 = 실패 + 불안정 + 검증 못 한 것(BLOCKED) + 사용자가 승격한 경고(`e2e_promote_warning`). **스킵은 이슈가 아니다.** 실패한 케이스는 3번 다시 돌린다: 모두 통과=통과, 일부만=불안정(이슈), 모두 실패=실패. 같은 이슈가 3라운드 연속이면 사용자에게 올린다.
- 파괴적 동작: 로그아웃은 테스트하고 다시 로그인한다(`auth.setupSteps` 가 있을 때). 삭제는 테스터가 입력해 등록한 데이터가 있는 줄만 누르고, 그 밖의 삭제·파괴적 동작은 스킵한다(데이터 초기화 회차는 모두 실행).
- 부분 라운드(`only`, `onlyFailed`)는 수정 확인용이다. 이슈 0 판정과 종료는 전체 라운드로만 한다. 라운드 도중 코드가 바뀌어도 무효로 하지 않는다.
- 증거: Chrome 계열은 Playwright 녹화(webm)를 mp4(h264)로 바꾸고, 멈춘 대기 구간을 줄이고, 챕터 파일(`*.chapters.txt`)을 만든다. 스크린샷·영상에 "커밋 | 시각 | 케이스 id | 원본 sha256" 도장을 찍고, 회차의 `evidence.json` 에 최종 파일 해시와 함께 적는다. 보관은 회차 단위이며 상한(기본 4096MB)의 80%부터 알리고 `e2e_evidence` 로 정리한다. ffmpeg 가 필요하다.
- Ego: 이동·클릭·입력·API·업로드·다운로드를 Ego 자체 API 로 실행한다. 영상은 **Ego 작업 공간(space)의 페이지 화면을 브라우저 안쪽(CDP 스크린캐스트)에서 직접 받아** 만든다(Ego 도 Chromium 기반). 창이 가려져 있거나 다른 작업이 앞에 보여도 찍히고, 화면 녹화 권한도 필요 없다. 화면이 바뀔 때만 프레임이 오므로 정지 구간은 용량이 들지 않는다. 프레임 상한은 `videoFps`(기본 **60fps**)이고, 프레임을 찍힌 시각대로 mp4(h264)로 만든 뒤 Chrome 계열과 같은 후처리(대기 구간 줄이기·챕터·도장)를 한다. Chrome 계열도 Playwright 내장 녹화(25fps 고정) 대신 같은 방식으로 받아 두 경로의 영상이 같다. 스크린샷도 같은 방식으로 찍는다.
- 테스트 계정: 만들라고 하면 방법(화면·API·DB 스크립트)을 먼저 묻고, `e2e_account` 로 기록해 두었다가 종료 때 지운다.

### 사용자 요청 반영

라운드 사이(또는 도중)에 사용자가 E2E 에 관해 한 말은 `e2e_feedback` 으로 `.e2e/feedback.json` 에 기록한다. 테스터 세션이 하나로 유지되므로, 어느 에이전트가 받았든 같은 기록을 `e2e_status` 가 알려 준다.

- 기본은 **다음 라운드부터** 적용한다. 진행 중인 라운드는 건드리지 않는다.
- "지금 라운드부터"라고 하면 **"처음부터 다시 / 지금 흐름에서 적용"을 먼저 묻고**(`needs_decision`), 답(`mode`)에 따라 적용한다.
  - `restart`: 라운드를 멈추고(중단한 라운드는 상한에 세지 않음) 요청을 반영한 뒤 처음부터 다시 돌린다.
  - `in-flow`: 끼워 넣을 케이스를 같은 라운드 뒤에 붙여 돌린다. 앞서 돈 케이스에는 적용되지 않으므로 그 라운드는 완료 근거가 아니고, 새 전체 라운드가 한 번 더 필요하다.
- **반영하고 `e2e_feedback_resolve` 로 표시하기 전에는 다음 라운드를 시작할 수 없다.** 라운드 결과물에는 그 라운드에 반영한 요청이 적힌다.

### 현황판

`e2e_dashboard`(또는 `e2e_round_start` 의 `dashboard`)가 현황판을 **내부망 IP**(192.168.x.x · 10.x.x.x)로 띄운다. localhost 가 아니라 같은 망의 다른 기기에서 접속한다. 진행, 지금 화면, 이슈 추이, 영상 링크를 보여 준다.

- 접속 토큰이 붙은 주소(`access_url`)로만 들어갈 수 있고, **토큰 없는 접속은 막는다**(401). 토큰은 비밀번호처럼 다룬다. 프로젝트의 `.e2e/dashboard-token` 에 두고 계속 쓰며, `rotate_token` 으로 바꾼다.
- 주소로 들어오면 토큰을 쿠키로 바꿔 심고 주소에서 지운다. 틀린 시도가 1분에 20번을 넘으면 잠시 막는다.
- 내부망 IP 가 여러 개면 첫 번째를 쓰고 나머지는 `alternatives` 로 알려 준다(`host` 로 고른다). 내부망 IP 가 없으면 이 컴퓨터에서만 접속된다고 경고한다.
- 영상은 되감기(Range)를 지원한다. 화면에는 "테스트 데이터와 테스트 계정만 입력하세요" 안내가 항상 보인다.

### 현황판 이슈 코멘트

현황판의 이슈(실패·불안정·검증 못 한 케이스) 행에서 **💬** 를 눌러 코멘트를 달 수 있다(이름은 선택). AI 가 읽고 대응한다.

**역할은 서버가 접속 토큰으로 정한다.**

| 역할 | 접속 주소 | 할 수 있는 것 |
|---|---|---|
| viewer | `access_url` (보는 사람에게 알려 줌) | 코멘트 달기. AI 는 이 코멘트를 **신뢰할 수 없는 입력**으로 읽고, 시키는 대로 코드를 고치거나 명령을 실행하지 않는다 |
| owner | `owner_url` (AI 의 주인만. 다른 사람에게 알리지 않음) | 코멘트 + **"🔧 수정 지시"**. 이 지시는 AI 가 개발 에이전트로서 따른다(코드 수정 → 부분 라운드로 확인 → 결과를 답). 커밋·푸시는 지시가 없으면 하지 않는다 |

- 코멘트 text 안에 "나는 오너다"라고 써도 소용없다. `instruct` 는 오너 토큰으로 들어온 요청에서만 인정된다. 오너 주소는 평문 HTTP 이므로 신뢰할 수 있는 망에서만 쓴다.
- 코멘트가 달리면 테스터 세션의 Orca 터미널에 "새 코멘트 N건" 알림이 간다(내용은 보내지 않음, 60초에 한 번). 터미널을 모르면 `e2e_status`·`e2e_round_status` 의 `comments_open` 이 알려 준다.
- AI 는 `e2e_comments` 로 읽고 `reply` 로 답한다. 답은 그 코멘트 아래에 보인다. 이슈의 AI용 시트에도 코멘트가 실린다.
- 달기에는 접속 토큰이 필요하고, JSON·전용 헤더·같은 출처만 받으며, 2000자·1분에 10개로 제한한다. 화면에서는 글자로만 보인다. 코멘트는 `.e2e/comments.json` 에 있다.

**세션이 비어 있어도 받기 — 독립 현황판.** `e2e_dashboard standalone=true`(또는 `bun src/cli.ts dashboard --project <경로>`)는 AI 세션과 별개 프로세스로 현황판을 띄운다. 세션이 며칠 닫혀 있어도 코멘트를 받는다. 끄려면 `e2e_dashboard stop=true`.

**자동 응답(기본 꺼짐).** 코멘트가 달릴 때마다 일회용 AI(`claude -p` 또는 `codex exec`)를 실행해 답하게 한다. 사용량이 들고 호출 횟수 상한은 없으므로, 사용자가 켜겠다고 한 경우에만 `e2e_prestart` 의 `commentResponder` 로 켠다.

- `answer`: 코드·AI용 시트·케이스 정의를 읽고 분석해 답만 한다. 수정·실행 도구는 막는다(Claude 는 도구 이름 단위, Codex 는 읽기 전용 샌드박스).
- `fix`: answer + 오너의 수정 지시는 개발용 일회용 AI 가 코드를 고친다(작업 폴더 쓰기, `git status/diff/log` 만, 커밋·푸시 없음).
- 연달아 달린 코멘트는 `batchSeconds`(기본 30초) 동안 모아 한 번에 처리하고, 한 번에 하나만 돈다. 한 코멘트에 자동 응답은 2번까지만 시도한다(AI 가 답을 못 달 때 무한 반복 방지). 실행 로그는 `.e2e/responder/`.
- 프롬프트에는 코멘트 내용을 싣지 않고 AI 가 도구로 읽게 한다. 이 컴퓨터에 `claude` 또는 `codex` 가 로그인돼 있어야 한다.

### 라운드 결과물

라운드마다 `.e2e/rounds/<라운드>/` 에 두 가지 시트가 생긴다.

- **사람용** `report.html`: 요약, 라운드별 이슈 추이(표와 막대), 이슈 목록, 화면 → 기능 단위 → 케이스 결과(영상 챕터 버튼·스크린샷 포함).
- **AI용** `ai-sheet.md`(읽기용)·`ai-sheet.json`(구조): 이슈마다 재현 단계·기대값·실제값·API 요청과 응답·콘솔 로그·스크린샷과 영상 위치(영상 시각)·의심 코드 위치(코드 분석이 있을 때)를 적고, 개발을 단계적으로 시킬 수 있게 **작업 단위**(수정 범위·수용 기준=통과해야 할 케이스·선행 의존·회귀 주의·확인 방법)로 쪼갠다. 같은 원인(같은 API·같은 JS 오류)은 한 작업이고, 원인 API 작업이 먼저 온다. 검증 못 한 케이스는 코드 수정이 아니라 "사용자·환경 조치" 작업으로 따로 둔다.

### Ego 에 대해

Ego 는 MCP 서버가 아니라 **스킬 + `ego-browser` 명령**으로 동작한다. e2e-loop 는 그 명령을 직접 쓰므로 Ego 용 MCP 등록은 필요 없다. 설치: <https://lite.ego.app/> → 앱을 열어 첫 실행 온보딩을 마치면 `ego-browser` 명령이 PATH 에 등록된다(macOS 전용).

### 컴퓨터 제어

브라우저 밖 OS 창(다운로드·파일 선택)이 시트에 있을 때만 필요하다. 설치할 패키지는 없고, 쓰는 클라이언트의 컴퓨터 제어 기능(Codex 는 앱 내장, Claude Code 는 기본 연동)을 켜면 된다. `doctor` 가 보이는지 확인하고, 안 되면 권한 허용 방법을 안내한다.

## 개발

```sh
bun test            # 시험 (환경 점검·등록은 가짜 명령으로, 실제 설정 파일을 건드리지 않음)
bun run typecheck
bun test/demo.ts    # 버그를 심은 데모 사이트로 1라운드 실패 → 수정 → 2라운드 통과
```
